# V2 physical validation: 2026-09-14

**PASS after explicit NVS initialization.** The unchanged V2.0.0 firmware
loaded eight signed-Q10 rows (72 coefficients), returned all expected scores
for three input vectors, saved the head, and returned the same scores after
a real hardware reset. This closes the physical evidence gap in
[issue #15](https://github.com/tylorsaling-source/SSOS-ESP32/issues/15).

## Execution and recovery

1. `scripts/validate-v2-windows.ps1 -Port COM20 -Yes` validated image hashes,
   flashed the four images, and digest-verified all four. All 24 initial
   inference outputs passed, but `SAVE` returned `ERR save failed` at 22:34:42Z.
   The harness correctly stopped with FAIL.
2. The release partition table identifies `nvs` at `0x9000`, length `0x5000`.
   With the user's authorization to use the board and discard its contents,
   `python -m esptool --chip esp32s3 --port COM20 --after hard-reset erase-region 0x9000 0x5000`
   initialized only that NVS region. The old contents were not extracted, so
   the exact cause of the old NVS failure is undetermined.
3. `scripts/validate-v2-windows.ps1 -Port COM20 -SkipFlash` ran from
   22:35:34Z to 22:35:39Z. It installed the fixture, ran three vectors,
   received `OK saved`, used Esptool's non-writing `read-mac`/hard-reset path,
   reconnected, and reran all three vectors. All checks passed.

The successful JSON truthfully says `flash.status=preexisting` and
`read_back_verify=false`: that invocation skipped flashing. The preceding
flash/native-tool transcripts establish the image that remained installed through the
NVS initialization and passing test. It is not a second, unrecorded firmware.

## Numerical and reset results

The [fixture](fixture.json) contains all 72 integer coefficients, all three
9-value inputs, all 24 expected outputs, and expected argmax values. Expected
scores are `sum(q10[row][col] / 1024 * input[col])` for each of the eight rows.
The JSON reports every observed output before and after reset.

| Vector | Outputs before / after | Maximum absolute error in either phase | Argmax |
| --- | --- | --- | --- |
| mixed | 8/8 / 8/8 | 0.000000468750000149 | 4 |
| first-axis-and-bias | 8/8 / 8/8 | 0.000000375000000052 | 2 |
| second-mixed | 8/8 / 8/8 | 0.000000351562500001 | 0 |

Tolerance: **0.00002 absolute per score**, including the serial console's
six-decimal formatting. All argmax values also matched. `MODEL` reported
`ready=1 source=packet-bank encoding=q10 rows=8 dims=9 outputs=8 weights=72`
after restart. Boot count increased from 1 to 2, receive count returned to 0,
and 10 saved packets were present. No rows were resent after the reset; the
cache was reconstructed by firmware from NVS.

This demonstrates persistence across a hardware reset. USB power was not
physically disconnected; it does not establish a power-loss endurance test.
The initial failure means migration from arbitrary existing NVS is not proven.
